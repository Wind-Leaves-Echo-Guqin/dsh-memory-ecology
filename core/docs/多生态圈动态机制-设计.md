# 多生态圈动态机制 · 设计文档

- 时间：2026-10-31
- 状态：本文件随本轮实现落地；机制口径以此为准，README/ARCHITECTURE 后续同步
- 需求来源：用户 2026-10-31 面谈定稿（主/副生态圈模型 · 多圈并存 · agent 主导激活 · 两层筛选 · 宇宙泡视觉另期）

---

## 0. 一句话

主生态圈是大气层（物理法则 + 气候 + 基础物种，常驻、靠前、不可挤掉）；
副生态圈是可动态挂载的特化泡（项目专属记忆，末端注入、热加载、用完分离）；
写入先经投递方声明初筛、再经门①判圈终审纠偏。

## 1. 用户口径（原话级约束，实现不得违背）

1. 主圈与副圈**有联系但不过度耦合**；副圈是主圈的**特化**（如大型项目专属承载）。
2. 实际施工时，当前记忆系统**以副圈的特化记忆为主导**，但**主圈的根本性规定仍生效**。
3. **不要假定工作时只能启用一个副圈**——多圈可同时启用、可重叠。
4. 副圈**会话中动态激活**，触发器归 **agent 主导**（挂载/分离工具，精准切割；
   某个圈的经验用完即可分离）。
5. 注入拓扑：**主在尽量靠前的位置、常驻加载；副圈末端注入、动态热加载
   （不重启会话）**；动态加载时 agent 能按任务精准切割。
6. 写入**先筛选再定主/副**：两层混合——投递方初筛 + 门① LLM 终审纠偏。
7. 主圈常驻内容三层：**物理法则**（生态不变量）、**气候**（USER.md 用户画像）、
   **基础物种**（global 高频通用经验）——各自有不可挤掉的通道。
8. 首批副圈：`dsh-eco-dev`（dsh 生态开发）、`quant-lab`(量化实验室)。

## 2. 概念 → 机制映射（含既有件复用）

| 概念 | 机制 | 载体 |
|---|---|---|
| 物理法则 | `charter` 注入段（字节稳定，仅版本/配置变更时变） | `systemPrompt.section 'eco:charter'`（order 9005，目录段之前） |
| 气候 | USER.md 摘要，变更才增量注入 | 既有 L1 pre-step 通道（`eco:l1` 快照消息） |
| 基础物种 | MEMORY.md（门② promote 的高频条目）+ 全局目录（命中排序） | 既有 L1 pre-step + 既有 `eco:catalog` 段 |
| 副圈目录 | 每圈一份物化目录（既有 `materialize`），按挂载集合拼装 | pre-step 尾段消息（`eco:circle` 快照，**新**） |
| 副圈激活/分离 | agent 工具 attach/detach + 落账 + 预算闸 | `memory_circle_attach/detach/list`（**新**） |
| 写入初筛 | 投递方 `deposit --scope`（既有；scope 合法性校验） | 核心 CLI |
| 写入终审 | 门①可插拔判圈 judge（LLM 由调用方注入，核心保持纯 stdlib） | `gates.integrate(scope_judge=…)`（**新**） |
| 驯化数据 | 跨圈命中统计（routed 圈会话命中 attached 圈条目） | `circle_hit` 账表 + `circles-stats`（**新**） |

### 为什么 charter 段只放物理法则

前缀字节稳定是成本铁律（改一字节 = 全量重新 prefill）。三层里只有物理法则
是"版本/配置级"稳定内容；气候与基础物种天然随使用演化，走 append-only 的
pre-step 通道（L1 增量注入，v3.2.2 已落地）代价最小。两层加起来就是
"主在尽量靠前（charter 前缀 + 命中排序目录）+ 主圈规定不可挤掉
（charter 段无预算竞争、L1 有独立 1500 字符预算）"。

## 3. 注入拓扑 v2（前主后副）

```
systemPrompt（前缀，字节稳定优先）
  ├─ eco:charter   (9005)  物理法则，~200 字符，仅版本/配置变更时变
  └─ eco:catalog   (9100)  全局目录（= 主圈基础物种滚动层），≤600 字符

对话消息（末端，append-only，随 compaction 自然滚出）
  ├─ eco:l1        L1 常驻（MEMORY.md=基础物种常驻层 + USER.md=气候），
  │                首轮全量 ≤1500，变更时增量（v3.2.2 既有）
  └─ eco:circle    挂载圈目录合集（routed 圈默认挂载 + agent 主动 attach），
                   ≤900 字符总闸，变更才注入，分离即停
```

**与 v3.2.2 的差异（重要）**：路由圈不再用 `systemPrompt.section` 同名段遮蔽
——遮蔽把圈目录放进前缀，既不满足"副圈末端注入"，也无法会话中热切。
v2 里路由圈是**默认挂载**的副圈（attached 集合的常任成员），与其他挂载圈
同走尾段通道。全局目录段从此只承担主圈内容，前缀更稳定。

**agent/created 行为不变**：仍按 cwd 算 routed 圈（检索/加载的默认边界），
只是注入位置移到尾段。

## 4. 挂载协议（agent 主导激活）

### 工具（插件注册）

- `memory_circle_list()` → 可挂圈清单（id/名称/条目数/只读/attachable/当前挂载态）
  + `circles-stats` 的跨圈命中建议（"A 圈在 B 圈会话被命中 ≥N 次 → 建议挂载"）。
- `memory_circle_attach(circle)` → 校验（已声明、attachable、未挂载）→ 核心
  `circle-attach` 落账并返回该圈目录载荷 → 进入挂载集合 → **下一轮起**尾段注入。
- `memory_circle_detach(circle)` → 移出集合 → 核心 `circle-detach` 落账 →
  停止注入；已注入的历史消息不撤回（append-only），随 compaction 自然滚出。

### 预算闸

- 每圈目录用自己的 `circles.json budget_chars`（用户授权的圈级预算）；
- 尾段总闸 `circleTailMaxChars`（默认 900）：**按最终文本实长判定**（头行与
  丢弃标注都计入预算）；放不下的圈整圈丢弃、后面放得下的小圈仍可进；
  因丢弃标注反超预算时从 included 尾部继续收缩。丢弃必须显式标注
  （`（超预算未注入：x——先 detach 释放预算）`）；routed 圈最先入集合，
  因此天然最不容易被丢。

### 安全边界

1. **attach 是显式工具调用，不是模型参数走私**：S3 fail-closed 语义保持——
   `memory_search/load` 的 scope 允许集合从 `{routed}` 扩为 `{routed} ∪ attached`；
   模型只能指向**已挂载**的圈，未挂载圈一律拒绝（与 v3.2.2 同口径，不回退）。
   **无圈会话的检索显式限 `--scope global`**（质量门①安全测试探测 4 的修复）：
   省略 `--scope` 在核心语义里是全库直通，插件绝不允许这个默认值出现；
   跨圈的正门只有 memory_circle_attach。
2. `circles.json` 新增可选字段 `attachable`（默认 **true**）：声明圈即授权挂载，
   `attachable: false` 显式退出。机密项目用它可以"可写不可挂"。
3. attach/detach 全部落 ledger event（`circle.attach` / `circle.detach`）：
   谁、何时、挂了什么，账上可查。
4. 挂载圈的目录载荷 = 该圈 + global（核心 `catalog_payload` 圈过滤，既有保证），
   **绝不含第三圈条目**。
5. 降级矩阵：核心不可用 → 工具报错但会话不死（fail-open）；目录物化缺失 →
   attach 返回空目录（fail-open）；attachable=false 或未声明 → **fail-closed 拒绝**。

## 5. 两层写入筛选

### 第 1 层 · 投递方初筛（既有，收紧）

- `deposit --scope`：显式声明（多值不做——指纹含 scope，"同一句话在两个项目
  里是两条独立记忆"是既有口径，多值 deposit 会造成同文双生）。
- scope 为空 → global；cwd 路由已有 `route` 命令可查（投递方自行调用）。

### 第 2 层 · 门①判圈终审（新，可插拔）

- `gates.integrate(..., scope_judge=None)`：judge 是纯函数
  `judge(body, current_scope, options) -> scope | None`
  （`options` = 已声明圈 id + global；None 表示"不动"）。
- 核心保持**纯 stdlib**：LLM judge 由调用方注入（与 `distill(llm=…)` 同模式）。
  生产 src 线的 `lib/llm.py` 包装是部署期接线点，不在核心内。
- 判圈生效 = 重写该 detail 的 `fm.scope`（文件名不变）+ 落 `gate_log`（action
  `RESCOPE`，记 from → to）+ 回执进 `integrate` 返回值（`rescoped[]`）。
- fail-open：无 judge / judge 抛错 / verdict 不在 options → 保持原 scope，
  一切照旧。**判圈绝不丢内容，只挪归属。**
- 为什么不进 systemPrompt 式"实时改写"：圈归属是治理决策，走门①留账可回滚，
  符合"唯一写者 + 永不静默变更"。

## 6. 跨圈命中统计（驯化数据基础）

- 新账表 `circle_hit(ts, routed, scope, id, via)`：当一次 `search`/`load`
  发生在 routed 圈 A 的会话、而生效 scope 是另一圈 B（即 agent 挂载了 B 并
  命中其条目）时记一行。`via` = search/load。
- 接线：CLI `search`/`load` 增加可选 `--routed`（插件透传 `state.circle`）；
  插件侧零领域逻辑（只传参）。
- `circles-stats [--limit N]`：按 (routed, scope) 聚合 count/distinct/max-ts，
  `count ≥ CIRCLE_ATTACH_SUGGEST_AFTER`（默认 3）标记 `suggest=true` ——
  这就是未来"驯化晋升"与宇宙泡"泡间桥接"的数据源。
- 只增不改：`circle_hit` 是 append-only 账，无淘汰（与 hit 表同待遇）。

## 8. 配置新增（全部走 `config.py` 常量 + eco.toml 覆盖）

| 键 | 默认 | 含义 |
|---|---|---|
| `CHARTER_RULES` | 内置四条 | 物理法则条目（list[str]）；toml 写法 `[charter] charter_rules = [...]`（短名归一要求键名自带 `charter_` 前缀） |
| `CIRCLE_TAIL_MAX_CHARS` | 900 | 副圈尾段总闸（字符） |
| `CIRCLE_ATTACH_SUGGEST_AFTER` | 3 | 跨圈命中建议阈值 |
| `L1_INJECT_BUDGET_CHARS` | 1500 | （v3.2.2 既有）L1 注入预算 |

circles.json 圈条目新增可选字段 `attachable`（缺省 true；`false` = 可写不可挂），
`save_circles` 会归一成显式布尔存储。

## 9. 测试与验收口径

- 核心 pytest：charter 组装/字节稳定/预算；judge 判圈（命中/不命中/抛错/
  非 options）；circle_hit 记账与聚合；circle-attach 校验矩阵（未声明/
  attachable=false/重复挂载）。
- 插件 mjs：尾段拼装函数（预算闸/整圈丢弃/变更才注入）；guard 扩展
  （routed ∪ attached 放行、其他拒绝）；工具注册与参数契约。
- 回归红线：S3 跨圈泄漏用例（未挂载圈检索必须仍被拒）继续绿；
  `test_no_unlink_of_memories_anywhere` 继续绿。
- 质量门：两轮代码审查（各含变异/稳定性/安全性/OCR），中间插子代理漏洞扫描。

## 10. 明确不做（本轮）

- 历史记忆归圈（等机制稳定后由用户拍板）。
- 圈间迁移/驯化自动执行（本轮只建数据源 `circle_hit`，行为另期）。
- 副圈自己的"项目宪法"（charter 的圈级版本，等首批圈跑出数据再设计）。
- 宇宙泡 GUI / 知识网络 / 神经网络可视化（机制交付后的后续期）。
- 生产 profile 切换与热重载（红线：掐断活会话，单独排期）。
